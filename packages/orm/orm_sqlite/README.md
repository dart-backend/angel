# Angel3 ORM for SQLite

[![version](https://img.shields.io/badge/pub-v10.0.0-brightgreen)](https://pub.dev/packages/angel3_orm_sqlite)
[![Null Safety](https://img.shields.io/badge/null-safety-brightgreen)](https://dart.dev/null-safety)
[![License](https://img.shields.io/github/license/dart-backend/angel)](https://github.com/dart-backend/angel/tree/master/packages/orm/orm_sqlite/LICENSE)

SQLite support for Angel3 ORM. SQLite 3.35 or later is required. It has two executors:

| | `SqliteAsyncExecutor` | `SqliteExecutor` |
|---|---|---|
| Driver | [`sqlite_async`](https://pub.dev/packages/sqlite_async) | [`sqlite3`](https://pub.dev/packages/sqlite3) |
| Statements run | in background isolates: they do not block the isolate that gives them | on the isolate that gives them, which waits for each |
| Connections | a pool of one that writes and several that read, in WAL mode | one |
| A query that reads, outside a transaction | runs at once, on a connection that reads, and sees the rows as they were before the transaction | waits for the transaction to end |
| In-memory database | only on one connection (see below) | yes |
| Use it for | a server | tests, command-line programs, scripts |

Both store values the same way, so a database written by one can be read by the other.

## Usage

```yaml
dependencies:
  angel3_orm: ^10.2.0
  angel3_orm_sqlite: ^10.0.0
  sqlite_async: ^0.14.7 # for SqliteAsyncExecutor
  sqlite3: ^3.9.0 # for SqliteExecutor
```

```dart
import 'package:angel3_orm_sqlite/angel3_orm_sqlite.dart';
import 'package:sqlite_async/sqlite_async.dart';

var database = SqliteDatabase(path: 'app.db');
var executor = SqliteAsyncExecutor(database);

// The queries generated by `angel3_orm_generator`, e.g.
var todo = await (TodoQuery()..values.title = 'Write docs').insert(executor);
```

Or, with `sqlite3`:

```dart
import 'package:sqlite3/sqlite3.dart';

var executor = SqliteExecutor(sqlite3.open('app.db'));
```

`SqliteAsyncExecutor` also takes one connection of a `sqlite3` database, such as one in memory for tests:

```dart
var executor = SqliteAsyncExecutor(
  SqliteDatabase.singleConnection(
    SqliteConnection.synchronousWrapper(sqlite3.openInMemory()),
  ),
);
```

### Migrations

Create the tables with the migrations of the models and `SqliteMigrationRunner` of `angel3_migration_runner` 10.1.0 or later, which takes a database of `sqlite3`. For `SqliteAsyncExecutor`, run them on the file before opening it with `sqlite_async`:

```dart
import 'package:angel3_migration_runner/sqlite.dart';

var raw = sqlite3.open('app.db');
await SqliteMigrationRunner(raw, migrations: [TodoMigration()]).up();
raw.close();

var executor = SqliteAsyncExecutor(SqliteDatabase(path: 'app.db'));
```

### Transactions

`executor.transaction` begins with `BEGIN IMMEDIATE`, so it holds the write lock of the database for its whole length. A query given outside it that writes waits for it to end. One that only reads, a `SELECT`, does too with `SqliteExecutor`, whose one connection the transaction holds, but not with `SqliteAsyncExecutor`, which reads on a connection of its own.

* Give the queries of a transaction to the executor its callback gets. They run in the transaction from anywhere, such as a stream listener made before it. A query given to another executor of the database runs in it only from the code of the callback; from elsewhere it is outside it, and one that waits for it to end must not be awaited by it. With `SqliteAsyncExecutor`, do not give statements to the `SqliteDatabase` itself in a transaction: `sqlite_async` throws a `LockError` for them.
* A transaction in a transaction is a `SAVEPOINT`, rolled back alone if its callback fails. An update or a delete of the ORM makes one. Savepoints run one at a time: a statement of the transaction given while one runs, as of `Future.wait` of several updates, waits for it to end.
* The transaction waits for the queries given in it that were not awaited before it commits.
* If SQLite rolls back the whole transaction after an error, as `RAISE(ROLLBACK)` of a trigger does, the transaction runs no more statements and throws a `StateError`, rather than running the rest outside it.

### How values are stored

| Dart | SQLite |
|---|---|
| `DateTime` | UTC text, `2024-03-10 12:34:56.000000Z`, which sorts in time order; a year before 0 or after 9999 throws an `ArgumentError` |
| `bool` | `0` or `1` |
| `List<int>`, such as a `Uint8List` | BLOB |
| `Map`, another `List` | JSON text, in which a `DateTime` is text as above |

## Known limitations

* **Dates:** The parts of a date (`where.createdAt.year`, ...) use `EXTRACT`, which SQLite does not have, and a comparison without the time (`includeTime: false`) compares text, which matches no stored time with `equals`
* **JSON:** The JSON queries (`where.data.property`, ...) are of PostgreSQL. A JSON column is read back as text, not as a `Map` or a `List`
* **`skipLocked`:** It has no effect, as SQLite locks the whole database, not rows
